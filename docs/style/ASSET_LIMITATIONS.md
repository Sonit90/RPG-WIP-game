# Asset Limitations

## Purpose

This document defines the technical limits for all game-ready environmental assets.

Assets generated by AI must be treated as **source assets**. Before entering the game, they must conform to these limits.

The target visual style is stylized, low-to-mid-poly fantasy similar to modern stylized MMORPG environments.

The priority order is:

1. Visual readability
2. Silhouette quality
3. Performance
4. Material quality
5. Geometric detail

Do not increase polygon count simply to preserve microscopic geometric detail.

---

# 1. Static Environment Assets

## 1.1 Triangle budgets

| Asset category            |   LOD0 |   LOD1 |  LOD2 |  LOD3 |
| ------------------------- | -----: | -----: | ----: | ----: |
| Tiny prop                 |    300 |    150 |    75 |    30 |
| Small prop                |  1,500 |    750 |   350 |   100 |
| Medium prop               |  5,000 |  2,500 | 1,000 |   300 |
| Large prop                | 12,000 |  6,000 | 2,500 |   750 |
| Hero prop                 | 25,000 | 12,000 | 5,000 | 1,500 |
| Large architectural piece | 20,000 | 10,000 | 4,000 | 1,000 |
| Hero architectural piece  | 40,000 | 20,000 | 8,000 | 2,000 |

These are **target limits**, not mandatory triangle counts.

Prefer fewer triangles whenever the silhouette and shading remain visually correct.

---

# 2. Vertex Limits

Vertex count should generally remain below:

| Asset             | Maximum LOD0 vertices |
| ----------------- | --------------------: |
| Tiny prop         |                   500 |
| Small prop        |                 2,000 |
| Medium prop       |                 6,000 |
| Large prop        |                15,000 |
| Hero prop         |                30,000 |
| Architecture      |                25,000 |
| Hero architecture |                50,000 |

### Absolute rule

A normal environmental asset should **never exceed 50,000 vertices**.

Assets above 50,000 vertices require explicit justification.

Assets above 100,000 vertices are not allowed in the runtime asset library.

---

# 3. AI Generation Limits

AI 3D generators may produce substantially more geometry than the runtime requires.

AI output should therefore be considered:

```text
AI OUTPUT
    ↓
Source Mesh
    ↓
Cleanup
    ↓
Decimation / Retopology
    ↓
UV
    ↓
LOD generation
    ↓
Runtime Asset
```

For Hunyuan3D or similar generators:

* Do not attempt to preserve the entire generated mesh.
* Preserve silhouette-critical geometry.
* Remove hidden geometry.
* Remove internal geometry.
* Remove microscopic surface geometry.
* Replace repeated geometric details with textures where appropriate.

---

# 4. LOD Requirements

Normal environmental assets should have at least:

* LOD0
* LOD1
* LOD2
* LOD3

Very small assets may use fewer LODs.

## Recommended reduction

```text
LOD0 = 100%
LOD1 = 50%
LOD2 = 20%
LOD3 = 5-10%
```

Example:

```text
10,000 triangle asset

LOD0 = 10,000
LOD1 = 5,000
LOD2 = 2,000
LOD3 = 500
```

The reduction should be based on **visual error**, not blindly on percentages.

LOD transitions should be determined primarily by screen-space size.

Modern engines use screen size and/or geometric error to determine appropriate LOD transitions.

---

# 5. Maximum Material Slots

## Standard assets

Maximum:

**4 material slots**

Preferred:

**1-2 material slots**

## Large assets

Maximum:

**6 material slots**

## Hero assets

Maximum:

**8 material slots**

Avoid creating separate materials for tiny visual differences.

Use a shared texture atlas where practical.

---

# 6. Texture Resolution

## Default

Most environmental assets:

**2048 × 2048**

## Small props

**1024 × 1024**

## Tiny props

**512 × 512**

## Large / hero assets

**2048 × 2048**

Maximum:

**4096 × 4096**

4K textures require explicit justification.

Do not use 4K textures simply because the AI generated a high-resolution texture.

---

# 7. Texture Channels

Standard PBR assets may contain:

```text
Base Color
Normal
ORM
```

Where:

```text
R = Ambient Occlusion
G = Roughness
B = Metallic
```

Do not create separate grayscale textures for AO, roughness and metallic unless there is a specific technical reason.

---

# 8. UV Requirements

Every runtime asset must have:

* valid UV coordinates
* no unintended UV overlap
* no severe stretching
* no inverted UV islands
* sufficient padding
* consistent texel density

## UV padding

For 2K textures:

Minimum:

**8 px**

Preferred:

**16 px**

For 4K textures:

Minimum:

**16 px**

---

# 9. Texel Density

Target environmental texel density:

**256-512 px/m**

Preferred default:

**512 px/m**

Do not use extremely high texel density for tiny details.

Large environment pieces should maintain approximately consistent texel density with neighboring assets.

---

# 10. Mesh Structure

Avoid:

* non-manifold geometry
* zero-area triangles
* duplicate vertices
* duplicate faces
* internal faces
* hidden geometry
* unnecessary bevel geometry
* extremely thin geometry
* disconnected accidental components
* excessive subdivision

The final mesh must have:

* valid normals
* valid tangents
* valid UVs
* correct winding
* no obvious shading artifacts

---

# 11. Smoothing / Normals

Use smooth shading where appropriate.

Use hard edges where required by the stylized art direction.

Do not solve every shading problem by adding geometry.

Prefer:

```text
correct normals
+
correct tangents
+
appropriate hard/soft edges
```

over excessive bevels and subdivisions.

---

# 12. Bevels

Bevel geometry should be used only when it contributes meaningfully to the silhouette or catches important lighting.

Do not bevel every edge.

Recommended:

```text
Hero prop:
1-2 supporting edge loops where necessary

Normal prop:
minimal bevel geometry

Tiny prop:
usually no geometric bevel
```

Small bevels can instead be represented through normal maps or baked textures.

---

# 13. Collision

Every interactive or blocking asset must have simplified collision geometry.

Preferred collision primitives:

* Box
* Capsule
* Sphere
* Simple convex hull

Avoid using the render mesh as collision.

## Collision complexity

Preferred:

```text
1-10 collision primitives
```

Normal maximum:

```text
20 primitives
```

Complex collision requires explicit justification.

---

# 14. Asset Scale

All assets must use real-world scale.

Default:

```text
1 engine unit = 1 meter
```

Examples:

```text
Torch        ≈ 1-2 m
Door         ≈ 2-3 m
Tree         ≈ 3-12 m
Small rock   ≈ 0.2-1 m
Large rock   ≈ 1-5 m
Building     ≈ 5-20+ m
```

Do not compensate for incorrect AI-generated scale inside the renderer.

Fix the source asset.

---

# 15. Pivot Requirements

Every asset must have an intentional pivot.

Examples:

### Ground props

Pivot at:

```text
bottom-center
```

### Trees

Pivot at:

```text
trunk base
```

### Rocks

Pivot at:

```text
bottom-center
```

### Doors

Pivot at:

```text
hinge
```

### Modular architecture

Pivot according to the modular grid.

---

# 16. Modular Environment Assets

Modular pieces should use a consistent grid.

Recommended base grid:

```text
0.5 m
```

Major structural increments:

```text
1 m
2 m
4 m
```

Pieces should snap together without visible gaps.

Examples:

```text
Wall_2m
Wall_4m
Wall_8m
Floor_2m
Floor_4m
Roof_4m
Column_1m
Door_2m
```

---

# 17. Foliage

Foliage should use substantially lower geometry budgets.

## Individual plant

```text
LOD0: 500-2,000 triangles
LOD1: 250-1,000
LOD2: 50-300
LOD3: billboard/impostor where appropriate
```

Avoid unique high-poly meshes for every leaf.

Use:

* cards
* clusters
* shared meshes
* instancing
* alpha-tested geometry where appropriate

---

# 18. Rocks

Rocks are silhouette-driven assets.

Recommended:

| Rock        |         LOD0 |
| ----------- | -----------: |
| Pebble      | 100-300 tris |
| Small rock  |    300-1,000 |
| Medium rock |  1,000-3,000 |
| Large rock  |  3,000-8,000 |
| Hero rock   | 8,000-15,000 |

Do not use geometry for small cracks and surface noise.

Use normal/detail textures instead.

---

# 19. Trees

## Small tree

```text
LOD0: 3,000-6,000 triangles
LOD1: 1,500-3,000
LOD2: 500-1,500
LOD3: billboard/impostor
```

## Large tree

```text
LOD0: 8,000-15,000
LOD1: 4,000-8,000
LOD2: 1,500-4,000
LOD3: billboard/impostor
```

Trunk silhouette receives priority over small branches.

---

# 20. Particles / VFX Meshes

Individual VFX meshes should generally remain below:

```text
2,000 triangles
```

Hero VFX meshes:

```text
maximum 5,000 triangles
```

Use shaders and particle systems for fine detail rather than geometry.

---

# 21. Draw Calls / Submeshes

Target:

```text
1-2 submeshes per normal prop
```

Maximum:

```text
4 submeshes per normal prop
```

Hero assets:

```text
maximum 8 submeshes
```

If an asset requires more, investigate whether materials can be combined.

---

# 22. Instancing

Repeated environmental assets must be designed for instancing.

Examples:

* rocks
* grass
* trees
* torches
* crates
* barrels
* fences
* architectural modules

Prefer:

```text
1 mesh + many instances
```

over:

```text
many unique meshes
```

For large numbers of static repeated objects, hierarchical/instanced rendering can significantly reduce the cost of managing individual objects.

---

# 23. Nanoscopic Detail

Do not model geometry that will occupy less than approximately:

**1-2 pixels on screen**

Examples:

Do NOT model:

* tiny scratches
* small wood grain
* tiny stone pores
* microscopic cracks
* tiny rivets

Represent them using:

* normal maps
* roughness
* base-color detail
* decals
* shader detail

---

# 24. AI Asset Acceptance Criteria

An AI-generated asset is accepted only if:

* silhouette is correct
* proportions are correct
* scale is correct
* topology is valid
* vertex count is within budget
* triangle count is within budget
* UVs are valid
* materials are within limits
* textures are within limits
* collision exists where required
* pivot is correct
* LODs exist where required
* no unnecessary hidden geometry remains

---

# 25. Runtime Hard Limits

These limits should be treated as hard runtime validation rules.

```text
Maximum vertices per normal asset: 50,000
Maximum vertices per exceptional hero asset: 100,000

Maximum triangles per normal asset: 40,000
Maximum triangles per hero asset: 80,000

Maximum material slots: 8

Maximum texture resolution: 4096×4096

Maximum normal environment texture: 2048×2048 preferred

Maximum collision primitives: 20

Maximum normal submeshes: 4
Maximum hero submeshes: 8
```

Assets exceeding these limits should fail validation unless explicitly marked as exceptions.

---

# 26. Recommended AI Generation Targets

When generating assets with AI, do not ask the model for the runtime limits directly.

Generate a higher-quality source mesh, then optimize it.

Recommended workflow:

```text
AI generation

Target:
20k-100k triangles

↓

Automatic cleanup

↓

Retopology / decimation

↓

Runtime target:

Normal prop:
1k-12k triangles

Large prop:
5k-20k triangles

Hero prop:
10k-40k triangles

↓

Generate LODs

↓

Bake textures

↓

Runtime validation
```

This gives the artist enough geometry to preserve the important silhouette while keeping the final runtime asset inexpensive.

---

# 27. Priority Rule

When reducing an asset, remove detail in this order:

```text
1. Hidden geometry
2. Internal geometry
3. Microscopic geometry
4. Surface noise geometry
5. Repeated geometric details
6. Small bevels
7. Small secondary forms
8. Medium secondary forms
9. Silhouette geometry ← preserve as long as possible
```

Never sacrifice the primary silhouette before removing invisible or insignificant geometry.

---

# 28. Engine Validation

Every imported asset should eventually be checked automatically for:

```text
vertex_count
triangle_count
material_count
texture_count
texture_resolution
uv_count
missing_normals
missing_tangents
missing_uvs
collision
lod_count
scale
bounding_box
```

The asset pipeline should report violations before the asset enters the runtime asset library.

This is implemented. See [`docs/asset-validation.md`](../asset-validation.md) for how to run
it, what each error code means, and how to add a rule or a category. This document stays the
specification: the validator's limits are transcribed from it, and where the two disagree
this document is right.

---

# 29. Philosophy

The goal is not:

> "Make the lowest-poly model possible."

The goal is:

> "Spend geometry only where the player can see and feel it."

A 5,000-triangle rock with a strong silhouette is preferable to a 30,000-triangle rock whose additional geometry is invisible.

Likewise, a 2K texture with good normal/roughness information is preferable to a 4K texture containing unnecessary detail.

**Silhouette > surface geometry > microscopic detail.**
